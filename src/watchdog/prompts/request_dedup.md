These are open "documents to go and get" requests from an investigation vault, each named by a different source document. Each request below is numbered. Return `groups`: one cluster per surviving request. Each cluster is `{"keep": <index>, "duplicates": [<indices>]}` — `keep` is the single index to KEEP, and `duplicates` lists the indices of requests that name the exact same real-world document, just described in different words. Every index must appear exactly once across all clusters (a request with no duplicate forms its own cluster with an empty `duplicates` list).

Only collapse requests that refer to the SAME specific document — the same order, the same affidavit, the same report, the same filing. Sharing a document type, a subject, a date, or a person is not enough on its own: two different affidavits sworn by the same person on different dates, or two different reports filed about the same case, are NOT duplicates — keep each as its own cluster. When two requests give slightly different dates for what otherwise looks like the same document (a likely drafting or extraction inconsistency) and everything else lines up — same party, same document type, same surrounding context — treat them as the same document.

When in doubt, keep both as separate clusters. A missed duplicate costs the journalist a few seconds re-resolving the same document twice; a wrongly merged pair could hide a document they still genuinely need to go and get.
